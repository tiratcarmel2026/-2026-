# מערכת קביעת תורים - עיריית טירת כרמל

מערכת production לקביעת תורים מקוונת למחלקות העירייה: Next.js (App Router) +
Supabase (בסיס נתונים) + Resend (שליחת מיילים) + Vercel (אחסון).

## מה יש כאן

- **בחירת מחלקה** ומסך קביעת תור עם תאריך ורשת שעות פנויות.
- **נעילת תור ל-15 דקות** בזמן מילוי הטופס, כדי שאף אחד אחר לא "יגנוב" את
  השעה בינתיים. הנעילה נאכפת ברמת בסיס הנתונים (unique index חלקי על שעות
  לא-מבוטלות), ולא רק בקוד - כך שגם בעומס/תחרות בין כמה תושבים בו-זמנית
  לא ייווצר תור כפול.
- **אישור תור** + שליחת מייל אמיתי (Resend) גם לתושב וגם למחלקה, כולל קוד
  ביטול.
- **ביטול תור** לפי מספר טלפון + קוד ביטול.
- **מסך ניהול** לכל מחלקה (`/admin/<מזהה-מחלקה>`), מוגן בסיסמה נפרדת פר
  מחלקה (משתני סביבה), עם טבלת התורים המאושרים וייצוא ל-CSV.

## דרישות מקדימות

- Node.js גרסה 20 ומעלה.
- חשבון [Supabase](https://supabase.com) (חינמי).
- חשבון [Resend](https://resend.com) (חינמי) ודומיין מאומת לשליחת מיילים.

## הרצה מקומית

1. התקנת תלויות:

   ```bash
   npm install
   ```

2. יצירת פרויקט Supabase, ואז הרצת הסכימה: פתחו את **SQL Editor** בפרויקט
   ה-Supabase, הדביקו את התוכן של `supabase/schema.sql` והריצו. זה יוצר את
   הטבלאות `departments` ו-`appointments`, אינדקס למניעת הזמנה כפולה, ונתוני
   דוגמה למחלקות (יש לעדכן שם/כתובת/טלפון/מייל אמיתיים לפני עלייה לאוויר -
   ראו את רשימת ה-`insert into departments` בקובץ).

3. יצירת קובץ `.env.local` על בסיס `.env.example` ומילוי הערכים:

   ```bash
   cp .env.example .env.local
   ```

   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` - מתוך Project Settings ->
     API בפרויקט ה-Supabase (יש להשתמש במפתח ה-service role, לא ב-anon key).
   - `RESEND_API_KEY`, `RESEND_FROM_EMAIL` - מתוך Resend, לאחר אימות דומיין
     (או שימוש בכתובת ברירת מחדל של Resend לבדיקות בלבד).
   - `ADMIN_SESSION_SECRET` - מחרוזת אקראית ארוכה, למשל `openssl rand -hex 32`.
   - `ADMIN_PASSWORD_<DEPARTMENT_ID>` - סיסמת ניהול נפרדת לכל מחלקה (שם משתנה
     הסביבה = מזהה המחלקה באותיות גדולות עם `_` במקום `-`, למשל
     `business-licensing` -> `ADMIN_PASSWORD_BUSINESS_LICENSING`).
   - `NEXT_PUBLIC_APP_URL` - הכתובת שבה האתר רץ (לצורכי קישורים במיילים).

4. הרצת שרת הפיתוח:

   ```bash
   npm run dev
   ```

   האתר יעלה בכתובת http://localhost:3000.

## פריסה ל-Vercel

1. דחפו את הפרויקט ל-GitHub (אם עוד לא נעשה).
2. ב-[vercel.com](https://vercel.com) בחרו **Import Project** וחברו את
   ה-repository.
3. בהגדרות הפרויקט ב-Vercel, הוסיפו את כל משתני הסביבה מ-`.env.example` עם
   הערכים האמיתיים (Environment Variables).
4. לחצו Deploy. תוך דקות תקבלו כתובת חיה כמו `your-project.vercel.app`.
5. לחיבור דומיין עירוני (למשל תת-דומיין של `tirat-carmel.muni.il`) - פנו
   למחלקת המחשוב של העירייה שתפנה רשומת DNS (CNAME) לכתובת שקיבלתם מ-Vercel,
   ותוסיפו את הדומיין תחת Domains בהגדרות הפרויקט ב-Vercel.

## מבנה הפרויקט

```
supabase/schema.sql          # טבלאות, אינדקסים, RLS, נתוני דוגמה
src/lib/                     # לוגיקת שרת: סלוטים, מייל, אימות ניהול, סופאבייס
src/app/api/                 # API routes: slots, hold, confirm, cancel, admin
src/app/                     # עמודי הקצה (בית, קביעת תור, ביטול, ניהול)
```

## מסך מצב עירוני / חמ״ל (`/matzav`)

מודול נוסף באותו פרויקט: מסך תצוגה למקרה חירום (למשל למסך במשרד מנכ״לית
העירייה/ראש העיר), מסונכרן בזמן אמת עם קונסולת ניהול נפרדת.

- **`/matzav`** - מסך תצוגה: כותרת התרעה, מספרי נפגעים, מפת Leaflet/
  OpenStreetMap של טירת כרמל עם סימוני אירועים, יומן עדכונים, צרכים
  ומשאבים, מספרי טלפון חשובים, ופאנל מצלמות שטח (אם הוגדרו). מתעדכן
  אוטומטית ללא רענון דרך Supabase Realtime.
- **`/admin/matzav`** - קונסולת ניהול (סיסמה משותפת ב-`ADMIN_PASSWORD_SITUATION_ROOM`)
  לעריכת כל הנתונים הנ״ל בזמן אמת - הם מופיעים על מסך התצוגה תוך שניות.
- **חיבור לפיקוד העורף**: פולינג של הפיד **הלא-רשמי** של `oref.org.il`
  (אותו פיד שבו משתמשות אפליקציות "התרעה באזורך" נפוצות), מסונן לערים
  שמכילות "טירת כרמל". **חשוב**: פיקוד העורף לא מפרסם API רשמי לצד שלישי -
  אין הסכם, אין SLA, והפיד עלול להשתנות או להיחסם. **זה לא תחליף לאפליקציית
  "התרעה באזורך" הרשמית או לצפירות עצמן** - הוא כלי עזר להצגת תמונת מצב
  מרוכזת, לא מערכת התרעת חיים. מומלץ לבדוק מול פיקוד העורף/עיריית טירת
  כרמל אם קיים ערוץ מידע רשמי (כמו הזנה למוקד 106) שעדיף לחבר אליו בהמשך.
- **מפה**: OpenStreetMap + Leaflet, ללא מפתח API וללא עלות. אינה כוללת
  ניווט (Waze/Google) - זו הצגת מפה עם סימוני אירועים, לא שירות ניווט.
- **"עיניים בחוץ" / מצלמות**: אין כאן חיבור אמיתי למצלמות אבטחה עירוניות.
  קונסולת הניהול מאפשרת להדביק כתובת הטמעה (iframe/HLS) של מצלמה קיימת אם
  ותי שתהיה כזו זמינה מהמערכת העירונית - זהו מקום מוכן להרחבה, לא יכולת
  מוכנה מאליה.

### הפעלה ראשונית

1. הריצו את `supabase/situation_room_schema.sql` ב-SQL Editor של Supabase
   (בנוסף ל-`schema.sql` הקיים).
2. הוסיפו ל-`.env.local`: `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` (מ-Project Settings -> API, מפתח ה-anon
   הציבורי - לא ה-service role), ו-`ADMIN_PASSWORD_SITUATION_ROOM`.
3. גשו ל-`/admin/matzav` להזנת נתונים, ול-`/matzav` לצפייה במסך התצוגה.

שני העמודים אינם מקושרים מהאתר הציבורי הראשי - יש להפיץ את הכתובות רק
לצוות הרלוונטי. `/matzav` (מסך התצוגה) אינו דורש סיסמה בכוונה, כדי שיהיה
אפשר להציג אותו על מסך גדול בקלות - יש לוודא שהכתובת עצמה לא מופצת
פומבית, ולשקול הגבלת גישה ברמת הרשת (למשל VPN פנימי) אם רוצים הקשחה
נוספת.

## הערה לגבי מידע פרטי של תושבים

המערכת אוספת שם, טלפון ומייל של תושבים - מידע פרטי במובן חוק הגנת הפרטיות.
לפני עלייה לאוויר בפועל מומלץ:

- לוודא מול הממונה על הגנת הפרטיות/היועץ המשפטי של העירייה שיש רישום/אישור
  מתאים למאגר מידע כזה.
- לשדרג את הגנת מסך הניהול (סיסמה זה מינימום לשלב ראשון) להתחברות אמיתית
  (למשל Supabase Auth) בהמשך.
- לקבוע מדיניות שמירה/מחיקה של פרטי תושבים (למשל מחיקה אוטומטית של תורים
  ישנים לאחר פרק זמן מוגדר).

זו אינה ייעוץ משפטי - רק תזכורת לבדוק את הנושא מול הגורמים המתאימים בעירייה.
